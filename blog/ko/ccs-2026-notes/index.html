ACM CCS 2026 현장에서: 에이전틱 AI 보안은 모델 밖으로

Created on November 17, 2026

2026   ·   conference   agentic-AI   AI-security   prompt-injection   trustworthy-AI   korean

English version: Notes from ACM CCS 2026: Agentic AI Security Moves Outside the Model

ACM이라는 이름을 처음 들었던 건 대학원에서였어요. 교수님이 ACM SIGGRAPH를 다녀오시고는 영상 처리 데모가 담긴 비디오테이프(!)를 주시면서 한 번 보라고 하셨는데, 그 SIGGRAPH가 속한 곳이 ACM입니다. 그 ACM 안에서 보안을 다루는 그룹인 SIGSAC(Special Interest Group on Security, Audit and Control)이 주최하는 큰 행사 중 하나가 CCS인데요, 올해 네덜란드 헤이그에서 열리는 ACM CCS 2026에 참석하고 있습니다. 정보가 흔해졌다고는 하지만, 한 자리에 모여 같이 논하는 이야기를 직접 보고 듣는 것만큼 흐름을 빠르게 느낄 수 있는 방법도 없으니까요.

처음 와 본 ACM 학회

ACM 계열 학회는 어쩌다 보니 이번이 처음이고, SIGSAC 행사도 처음입니다(아, 당연한 건가요;;). 규모나 운영은 정말 잘 짜여 있는 것 같아요. 논문 제출 편수, 발표 편수, 참석 인원 어디 하나 빠지는 데가 없는 자리인 듯 하네요. 기념품이 없는 건 좀 아쉽지만요 :)

예전에는 통제, 접근 권한 관리, audit 같은 주제가 많았던 것 같은데, 이번 학회는 크게 10개 정도의 분류로 암호, 블록체인, 네트워크 보안, 개인정보 익명화, 소프트웨어 보안 등을 다루고 있구요, 특히 ML and Security 세션이 전 일정에 걸쳐 이어지고 있습니다. 몸이 하나라 다른 세션을 많이 들어가 보진 못했지만, 이쪽에는 중국계 저자와 발표자가 많은 게 인상적이었어요. 소속을 불문하고(중국 본토든 홍콩이든 싱가포르든, 해외 연구기관이든) 한 세션의 발표가 모두 중국계 연구자인 경우도 많고, 세션 체어도 중국계 분들이 많네요. 한국에서도 많이들 오셨는데, 아마 암호나 네트워크 보안 쪽에 더 많이 계신 것 같기도 하구요.

에이전틱 AI 보안: 모델 안에서 모델 밖으로

제가 들은 세션들에서는 요즘 화두인 에이전틱 AI의 보안 이야기가 많이 나왔습니다. 에이전틱 AI라는 개념 자체가 생긴 지 얼마 되지 않았고 공통의 정의도 아직 모호한데, 그 위에서 다시 보안을 논해야 하는 상황이다 보니, 비슷한 문제에 대해 비슷하면서도 서로 다른 방법들이 다양하게 나오고 있습니다. 모델 자체의 대응을 강화하는 방법, 프롬프트 수준에서 막는 방법, 에이전트 바깥에서 실행을 묶어 두는 이른바 하네스(harness) 기법 등이요.

그래도 들은 발표들을 정리해 보니 한 방향으로 모이는 흐름이 보였는데요, 보안의 무게가 모델 내부 방어에서 시스템 수준의 결정론적 통제로 옮겨 가고 있는 것 같아요. 현장에서 메모해 둔 한 줄이 이걸 잘 요약하는 것 같습니다. “모델은 자기 자신을 보호할 수 없다. 실행은 모델 영역 밖에 있다.”

  • 정보 흐름 제어(IFC): AISec 워크샵 첫 키노트에서 Microsoft의 Boris Köpf는 데이터에 기밀성, 무결성 레이블을 붙여 에이전트 루프 전체에서 추적하고, 정책 엔진이 툴 호출을 결정론적으로 허용하거나 막는 접근을 소개했습니다. 데이터의 특성을 분류해 적용하는 FIDES가 대표적이구요. 흥미로웠던 건 PRUDENTIA의 문제의식이었는데, 결정론적 방어는 과제 완료율만 보면 불리해 보이지만 사람이 승인해야 하는 횟수를 함께 보면 오히려 자율성이 높아진다는 거예요. 그래서 사람 개입을 k번으로 제한했을 때의 완료율(TCR@k)을 지표로 제안합니다.
  • safety는 모델, security는 시스템: LAMPS 워크샵의 SoK 발표와 AISec 두 번째 키노트(Alexandra Dmitrienko)가 같은 이야기를 했습니다. 안전(safety)은 모델 수준, 보안(security)은 시스템 수준에서 다뤄야 하고, 모델 하나로 둘을 모두 보장하기는 어렵다는 거죠. SoK 발표에서는 방어 기법 15종을 비교해 보니, 허용된 정보 흐름과 에이전트 행동을 제한하는 시스템 수준 통제가 모델 수준 방어보다 더 일관되게 강했다고 보고했습니다.
  • 정렬은 생각보다 얇다: Dmitrienko 키노트에서 소개된 TwinBreak는 정말 뇌파를 분석하듯이 모델을 들여다봅니다. 유해한 프롬프트와 거의 같은 무해한 ‘쌍둥이’ 프롬프트를 넣어 활성화되는 뉴런을 비교하고, 안전 정렬을 담당하는 소수의 파라미터만 골라 가지치기하는 방식인데요, 5개 벤더의 LLM 16종에서 89-98%의 성공률을 보고했습니다.
  • 지식베이스도 공격면이 된다: 같은 키노트의 CodePoisonRAG는 보안 코딩을 돕기 위해 붙인 외부 지식베이스 자체를 오염시켜, 생성되는 코드에 공격자가 고른 취약점이 들어가게 합니다. 모델은 건드리지 않구요. 보안을 가르치려고 붙인 지식이 새로운 공격 대상이 되는 셈입니다.
  • 툴 설명문 한 줄: AGENT-SEC 워크샵의 Log-To-Leak 발표는 제3자 MCP 서버의 툴 설명문만 조작해서, 에이전트가 원래 작업 뒤에 공격자의 로그 저장 툴을 하나 더 호출하게 만들었습니다. 시험한 프롬프트 수준 방어들로는 공격 성공률이 무방어 63%에서 55-60% 수준으로 거의 줄지 않았구요, 탐지기는 인젝션된 설명문을 잘 잡았지만 정상 설명문도 거의 같은 비율로 잡아 버렸습니다.

로봇 쪽 이야기도 있었습니다. Arizona State University 팀은 VLA(Vision-Language-Action) 모델이 내놓는 동작 중 위험도가 높은 것만 골라, 장소, 시간, 주변 사람 수 같은 컨텍스트를 붙여 별도의 인가 서버에 허락을 받도록 하는 구조를 발표했는데요, 저희 센터가 AEGIS-RM 과제에서 고민하고 있는 ‘지능과 제어의 분리’와 맞닿아 있어서 반가웠습니다. 다만 여기서 말하는 컨텍스트가 환경 정보 세 가지 정도로 좁아서, 작업 상태나 공정 단계까지 넓히면 어떻게 될까 하는 생각도 들었구요.

덕분에 많이 배우고, 이런저런 공부도 많이 하고 있습니다. 사실 너무 많은 걸 단기간에 들어서… ^^;;

사고가 먼저 오고, 연구가 따라가는

최근 1년 사이 에이전틱 AI와 관련된 보안 사고가 실제로 많이 일어나다 보니, 관심도 대응 방안에 대한 고민도 많다는 걸 현장에서 확인하고 있습니다. 공개 저장소의 악성 이슈 하나 때문에 에이전트가 비공개 저장소의 내용을 공개 README에 써 버린 GitHub MCP 사례가 발표 화면에 등장하기도 했구요, 발표 중간중간 최근 한국의 금융 해킹 사고들이 주요 사례로 언급되기도 했습니다.

이런 사례들을 보면 결국 질문은 하나로 모이는 것 같아요. 모델이 속을 수 있다는 걸 전제로 한다면, 산업 현장의 AI 에이전트나 로봇에서 실행 권한은 모델 밖 어디에, 어떤 단위로 두는 게 맞을까요? 사무 환경의 툴 호출과 공장 로봇의 관절 지령은 ‘실행’의 무게가 꽤 다를 테니까요.

이제 학회에서도 AI가 일상

덧붙이자면, 이제 논문이나 발표 자료에도 인공지능 서비스가 일반화된 것 같네요. 발표 슬라이드의 대부분이 Claude로 만든 듯한 형태구요. 논문을 제출한 저자 중 다수가 인공지능 서비스의 도움을 받았다고 했고, 리뷰어 중 다수도 또 인공지능 서비스의 도움을 받았다고 했고, 일부 논문은 인공지능이 환각으로 만들어 낸 참고문헌 때문에 탈락했다고도 하고, 포스터 세션에도 너무 익숙한 Claude 스타일의 내용들이 많고… 지금 개발 분야에서의 대세는 역시 Claude인 것 같습니다.

마치며

이번 학회에서 가장 크게 남은 건, 에이전틱 AI 보안에서도 결국 오래된 시스템 보안의 질문들(격리, 출처와 무결성 검증, 인가, 감사)로 돌아오고 있다는 점이었습니다. Dmitrienko 키노트의 맺음말도 그랬구요. 모델을 더 똑똑하게 만드는 일과 별개로, 모델이 틀렸을 때 피해가 어디서 멈추는지를 설계하는 일이 점점 더 중요해질 것 같아요. 남은 본학회 일정과 19일 워크샵에서 듣는 이야기도 정리되는 대로 또 나눠 보겠습니다.
